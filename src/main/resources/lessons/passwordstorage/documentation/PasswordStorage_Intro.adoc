= Password storage

Passwords are difficult to store safely because an attacker who steals a credential database can test guesses on their own hardware. The storage design determines what the attacker needs and how much each guess costs.

In this lesson, you will learn why password storage needs:

* a password-specific key derivation function instead of a fast general-purpose hash;
* a unique public salt for every password;
* careful separation of any secret pepper from the password database.

The Daily Byte blog stores passwords for its readers and authors. Maria can publish and edit every article, so her account is the target.

You obtained a copy of the blog's user database. Each exercise shows a new version of its password storage. The password and the training wordlist are fictional. Do not enter a real password.

An attacker who has a password verifier can test guesses without contacting the application. This is an *offline attack*. Login rate limits do not slow it down.

This lesson examines which data an offline attacker needs and how much work each guess requires.
